# Конспект по Docker

## Образы

Docker-образ - преднастроенный образ ОС, содержащий минимальный набор компонентов для запуска определённого ПО. Чаще всего образы создают на основе Linux.

Docker Hub - централизованное хранилище Docker-образов.

Команды:
- `docker pull` - загрузить образ из Docker Hub
- `docker images` - просмотреть список локально установленных образов
- `docker image rm <образ>` - удалить локально установленный образ

## Контейнеры

Docker-контейнер - запущенная система, изолированная от хостовой ОС. Контейнер создаётся на основе образа.

Контейнеры могут взаимодействовать с хостовой ОС через тома (docker volumes) и проброс сетевых портов.

Команды:
- `docker ps` - получить список работающих контейнеров
- `docker ps -a` - получить список всех контейнеров
- `docker run [параметры] <образ> [команда]` - создать и запустить контейнер из образа
- `docker start/stop <контейнер>` - запустить/остановить контейнер
- `docker rm [-f] <контейнер>` - удалить контейнер, с флагом `-f` можно удалить запущенный контейнер
- `docker exec [-it] <контейнер> <команда>` - выполнить команду внутри контейнера, с флагом `-it` - в интерактивном режиме

Параметры команды `docker run`:
- `--name <название>` - название контейнера
- `-d` - (detach) запустить контейнер в фоне
- `-it` - (interactive) запустить контейнер в интерактивном режиме
- `-v <том>:<путь>` - (volume) примонтировать том к указанной директории внутри контейнера
- `-p <порт хоста>:<порт контейнера>` - пробросить порт в хостовую ОС

## Тома

Том - хранилище данных, доступное для контейнеров при монтировании тома.

Команды:
- `docker volume ls` - получить список томов
- `docker volume inspect <том>` - получить информацию о томе
- `docker volume rm <том>` - удалить том
- `docker volume create <название>` - создать том

Примечание: тома создаются автоматически при их монтировании.

## Dockerfile

`Dockerfile` - файл с инструкциями по созданию Docker-образа.

Команды:
- `FROM <образ>` - задать исходный образ
- `WORKDIR <путь>` - установить рабочую директорию внутри контейнера
- `COPY <src> <dest>` - скопировать файлы/директории с хоста внутрь контейнера
- `ADD <src> <dest>` - добавить файлы/директории в контейнер, в отличие от `COPY`, поддерживает скачивание файлов по HTTP[s]
- `RUN <команда>` - выполнить команду внутри контейнера
- `VOLUME ["<том>", "<том>", ...]` - примонтировать тома в указанных директориях внутри контейнера
- `EXPOSE <порт>` - вытащить порт наружу
- `USER <пользователь>` - переключить пользователя
- `HEALTHCHECK [--interval=<интервал>] [--timeout=<время ожидания>] [--retries=3] CMD <команда>` - задать команду проверки работоспособности контейнера
- `ENV <переменная>=<значение>` - установить переменную среды внутри контейнера
- `ARG <переменная>=<значение>` - установить переменную самого Dockerfile (build-time). Внутри контейнера она доступна не будет 
- `ENTRYPOINT <файл>` - установить точку входа по умолчанию
- `CMD ["<команда>", "<аргумент>", "<аргумент>", ...]` - установить команду по умолчанию

### Слои

Каждое изменение системы (`RUN`, `COPY`, `ADD`, ...) создаёт новый слой. Docker кэширует слои, чтобы ускорить сборку контейнера.

Например, если изначально в Dockerfile были такие команды:
```Dockerfile
FROM ubuntu:jammy
COPY a.txt /data/a.txt
COPY b.txt /data/b.txt
RUN cat /data/b.txt
```

А потом изменились на такие:
```Dockerfile
FROM ubuntu:jammy
COPY a.txt /data/a.txt
COPY b.txt /data/c.txt
RUN cat /data/c.txt
```

То Docker при сборке второй версии докерфайла не будет выполнять заново команду `COPY a.txt /data/a.txt`, ускорив таким образом процесс сборки.

### Multi-stage build

Каждая инструкция `FROM` создаёт отдельный stage. Stage нужны, чтобы можно было собрать необходимые компоненты итогового образа в полноценном окружении (например, если нужна компиляция C-кода), а потом перенести в итоговый образ *только результаты сборки*, не тратя место на ненужные в рантайме инструменты.

Stage нумеруются с нуля, для копирования файлов из предыдущих stage можно использовать команду `COPY --from=<номер stage> <путь в stage из параметра from> <путь в текущем stage>`

Пример докерфайла с multi-stage:
```Dockerfile
FROM python:3.11
WORKDIR /build

COPY requirements.txt .
RUN pip wheel -w libs -r requirements.txt

FROM python:3.11-slim
EXPOSE 8080

RUN apt update && apt install -y curl
RUN rm -rf /var/lib/apt/lists/*

VOLUME ["/var/log/app"]
ENV APP_LOG_FILE=/var/log/app/log.txt

RUN useradd -ms /bin/bash runner
RUN mkdir -p /var/log/app
RUN chown runner /var/log/app

USER runner
WORKDIR /home/runner

HEALTHCHECK --interval=30s --timeout=5s --retries=3 CMD curl --fail http://localhost:8080/health

COPY main.py .
COPY --from=0 /build/libs libs
RUN pip install libs/*.whl

CMD ["python3", "main.py"]
```

Здесь сначала для сборки Python-библиотек (wheels) используется полноценный образ Ubuntu размером более гигабайта, а затем собранные библиотеки устанавливаются в slim-версию Ubuntu размером менее 100 МБ, на которой и запускается приложение.

### Команды для работы с докерфайлами
- `docker build [-t <название образа>[:<тег>]] <путь к директории, содержащей Dockerfile>` - создать образ из Dockerfile


## Тегирование

Теги образов используются, чтобы указать на версию или особенности образа. Тег добавляется к названию образа с использованием символа `:`.

Команды:
- `docker tag <исходный образ>[:<исходный тег>] <новое название образа>[:<новый тег>]` - изменить название и/или тег образа
